# Missed-trade fixes

Base version: `1884f22aaf35a6c3a61f61294ee8c366598fe9b8`.

## Executable REST book recovery

A proactive REST refresh previously dropped the exchange timestamp while
marking the book LIVE. Live preparation then refused it until another
WebSocket update arrived. The production runner now uses a metadata-preserving
public book read. Token validation, timestamp bounds, receipt age, tick, hash,
generation and receive-revision fences remain enforced.

REST observations carry explicit provenance. They do not advance the ordered
WebSocket watermark or certify earlier venue-time books. Local book history
uses installation time, while freshness keeps the original response receipt
time, so slow decoding cannot rewrite the pre-move fair-value anchor.

## Failed FAK state propagation

An order whose complete trade set has authoritatively FAILED now publishes a
terminal zero-fill result after the existing stable-period and ledger checks.
The event loop removes its pending strategy slot or retracts its previously
reported provisional shares, cost, fill count and execution-quality sample.
Repeated reconciliation cannot refund the order twice.

Updates use the original order and round. Later fills, other pending orders,
opposite-side positions and a new round's state remain intact. Carry remains
the last same-side order's unfilled target: a late failure cannot change a
later order's remainder. Unknown, mixed, mismatched, incomplete or booked
evidence retains its existing reservation and risk handling.

## Current diagnostic verdicts

`sniper_why.py` uses fresh explicit live status and matching pause/resume
events. Historical pauses and errors no longer imply a current halt or a
required restart. Truncated or ambiguous reasons remain unknown until a
complete status disambiguates them. Later failed-settlement updates also
retract earlier provisional fill evidence in the printed verdict.

## Trusted server time during connection warming

The periodic public time request previously accepted a numeric error body
without checking HTTP status. It could replace the authentication clock with
an invalid offset. Initial refresh also converted boolean JSON values to
numbers before validation. Both paths now require HTTP 200 and a finite,
positive, non-boolean timestamp. Numeric bodies and the existing `time` and
`timestamp` fields are supported, together with `server_time`.

Invalid replies leave the last trusted sample unchanged. Connection warming
uses its existing failure backoff; the clock continues to age and refuses
orders if it becomes stale. Seven offline regressions cover this behavior.
This fixes clock validation, without demonstrating a faster live response.

## Validation

Optional warm-only execution is available with `SNIPER_WARM_ONLY=1` and
`SNIPER_HTTP=fast`. It skips cold opportunities, reconnects only through
background warming, and never retries a refused signed order. Timestamp,
durability and risk checks remain enforced. Ten additional in-memory tests
cover warm dispatch, cold skips, repeated sends, accounting and clock checks.
These tests plus the focused command below pass 144 cases. This mode avoids
cold connection setup; it does not speed up already-warm exchange responses.

54 new regressions cover the real parser/hub/book conversion, failed-order
reconciliation and strategy state transitions, and the diagnostic command's
printed output. Focused command, including existing freshness/cooldown cases:

```bash
python run_tests.py rest_book_metadata failed_fak_strategy sniper_why \
    binance_freshness sniper_cooldown p2_quiet_book
```

The review workspace passed all six suites (91 tests), source compilation,
and `git diff --check`. Additional existing feed/recovery and IOC/risk tests
passed in scoped checks. The earlier recovery stall was reproduced with plain
`asyncio.to_thread`, independent of bot code; a test-only selector wakeup
adapter allowed the ten non-socket recovery tests to pass.

The later record review and clock repair also pass these focused suites:

```bash
python run_tests.py warm_only clock_warm latency_target rest_book_metadata \
    failed_fak_strategy sniper_why binance_freshness sniper_cooldown \
    p2_quiet_book execution_audit
```

Together they contain 144 offline cases. The latency additions measure and
validate execution evidence; they do not establish live fills below 200 ms.

Complete integration validation still requires the repository's installed
SDK/signing dependencies and local socket support. This review environment
does not have those dependencies, blocks local AF_INET sockets, and has
WebSockets 16 outside the declared `<16` range. Run the full suite in the
pinned dependency environment:

```bash
python -m pip install -r requirements.lock.txt
python -m pip check
python run_tests.py
```

These fixes do not start or deploy the bot. The actual missed trade still
needs attribution against the deployed commit, paper/live mode, round and
runtime logs. The earlier `review_artifacts/repro_*.py` files are historical
pre-fix demonstrations; the new `tests_*.py` suites verify the repaired behavior.

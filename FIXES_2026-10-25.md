# Fixes 2026-10-25

From the review of `0533fa9`. Every change has a test that fails on `0533fa9`.

| ID | Change | Test |
|---|---|---|
| H1-window | **An executed FAK whose reply timed out could be settled NO_MATCH.** `LeanSender._after` handed the unknown-outcome resolver a copy of the row before stamping its `wall`, so `_resolve_ambiguity` dated the send from the clock *after* ~120s of `get_order` lookups and read the trade record from ~0.9s **after** the send. A FAK that matched in its first second (the usual case) was outside the window: reservation released, loss budget cleared, never booked (later an unexplained fill). Now the row is stamped first, and `_trade_history_verdict` reads the whole round: from `HISTORY_BEFORE_END_S` (600s) before its end, or 120s before the send if earlier. A late, missing or malformed send time can no longer narrow it. | `tests_execution_reliability.py`: `HistoryWindow`, `TimeoutThisRunProductionDelays` (production lookup delays on a virtual clock, a record that applies `after`). On `0533fa9` the executed order settles NO_MATCH. |
| Paper delay | `SNIPER_PAPER_EXTRA_MS` defaults to **200** (was 0; never applies live). On live's own 1,154 orders, 0 gave paper +$210.68 where live made +$1.42; 200 matched live's 21% fill rate (`a4406a7`). `0` brings the old paper back. | `tests_paper_realism.py` |
| Delay sample | `refresh_delays.py` rebuilds paper's delay sample from the live journal (last 7 days by default) in the shipped, sanitized format and prints old vs new quantiles and the `.env` line. The shipped sample (10-04..06) ran p90 480ms; live replies on 10-22 ran p90 966ms. **Run it on the VPS** - the live journal is not in git. | `tests_refresh_delays.py` |
| M3 | `SNIPER_KELLY_MIN_ENTRY` defaults to **0**. When set to 1, a minimum entry is never taken below the equity high-water mark (`minimum_entry_blocked: "realized drawdown"`). Its 37 fills of 10-15..10-21 lost $20.96 on $106; one bought 5 shares at an 18.7% drawdown where Kelly said 0. Not in the frozen spec: live accepts either value. | `tests_hybrid_strategy.py`: `test_minimum_entry_is_never_taken_in_a_realized_drawdown` |
| L7 | `tests_run.py` polls up to 1s for a killed holder's lock to be released (Windows frees it ~50ms after `wait()`). | Linux unchanged; Windows no longer fails. |

Trading-file digests re-approved in `tests_feeds.py`: `sniper_live.py`, `sniper_mode.py`.
Trigger, fair value, Kelly formula, prices, caps, cooldowns and the live dispatch path are unchanged.

## On the VPS

`.env` there was copied from the old bot, so the new defaults apply only where a setting is
unset. Check these two lines:

```dotenv
SNIPER_KELLY_MIN_ENTRY=0
SNIPER_PAPER_EXTRA_MS=200
```

Then refresh the paper delays from live and point paper at the file it prints:

```bash
.venv/bin/python refresh_delays.py
```
